Producer–Consumer System

A multithreaded C program coordinating shared data, bounded capacity, and orderly shutdown with POSIX threads.

The coordination problem

Multiple producers and consumers share a bounded circular buffer. Producers must wait for space; consumers must wait for data. The program uses POSIX threads, two semaphores, and a mutex to coordinate access.

Design decisions

  • The empty and full semaphores track available slots and queued items; the mutex protects the shared buffer and indices.
  • Each producer generates 20 items in the range 0–99. Buffer indices wrap with modulo arithmetic.
  • After all producers finish, the main thread inserts one −1 sentinel per consumer. Consumers release the lock and signal the empty slot before checking whether to exit.
  • Producer count, consumer count, and buffer capacity are command-line parameters. The README includes a 30-producer, 8-consumer, 3-slot test configuration.

FROM THE SOURCE

Shutdown without trapping the lock

The report describes an earlier deadlock when the poison-pill exit check was inside the critical section. The supplied implementation unlocks the mutex and signals the semaphore before exiting.

Read the implementation walkthrough

The program takes producer count, consumer count, and buffer capacity as arguments. Producers wait for empty slots, write items under a mutex, and signal full slots. Consumers perform the reverse operation. Once the producers finish, the main thread inserts −1 sentinel values so the consumers can exit, then joins them.

This is a source-based summary, not a transcript of the recording.

Debugging beyond the happy path

The team report also documents using GDB to trace a segmentation fault to a NULL-pointer dereference. The project brought synchronization, thread lifecycle, and practical debugging together in a compact systems-programming exercise.
